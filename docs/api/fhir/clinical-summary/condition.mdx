# Condition

<span className="fhir-maturity" data-level="3">Trial Use 3</span>
<span className="fhir-category">Clinical — Summary</span>

Clinical condition, problem, diagnosis or finding.

## Endpoints

The standard FHIR R5 interactions for `Condition` are mounted under your
selected release tier:

<ApiBase surface="fhir" path="/Condition" inline={false} />

| Interaction | Method | Path |
| --- | --- | --- |
| Read       | `GET`    | `/Condition/[id]` |
| Vread      | `GET`    | `/Condition/[id]/_history/[vid]` |
| Update     | `PUT`    | `/Condition/[id]` |
| Patch      | `PATCH`  | `/Condition/[id]` |
| Delete     | `DELETE` | `/Condition/[id]` |
| Create     | `POST`   | `/Condition` |
| Search     | `GET`    | `/Condition?...` |
| History    | `GET`    | `/Condition/[id]/_history` |
| Type-history | `GET`  | `/Condition/_history` |

All calls expect FHIR-flavoured JSON
(`Content-Type: application/fhir+json`) and accept the standard
`Accept: application/fhir+json` header.
