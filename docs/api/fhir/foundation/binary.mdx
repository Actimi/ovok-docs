# Binary

<span className="fhir-maturity" data-level="5">Normative</span>
<span className="fhir-category">Foundation</span>

Raw binary content (image, PDF, etc.).

## Endpoints

The standard FHIR R5 interactions for `Binary` are mounted under your
selected release tier:

<ApiBase surface="fhir" path="/Binary" inline={false} />

| Interaction | Method | Path |
| --- | --- | --- |
| Read         | `GET`    | `/Binary/[id]` |
| Vread        | `GET`    | `/Binary/[id]/_history/[vid]` |
| Update       | `PUT`    | `/Binary/[id]` |
| Patch        | `PATCH`  | `/Binary/[id]` |
| Delete       | `DELETE` | `/Binary/[id]` |
| Create       | `POST`   | `/Binary` |
| Search       | `GET`    | `/Binary?...` |
| History      | `GET`    | `/Binary/[id]/_history` |
| Type-history | `GET`    | `/Binary/_history` |

All calls expect FHIR-flavoured JSON
(`Content-Type: application/fhir+json`) and accept the standard
`Accept: application/fhir+json` header.
